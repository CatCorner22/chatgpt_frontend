# References for a bounded source-aware trial patch

**Sources inspected: 18 November 2026 (UTC).** This document supports the proposed slice in [Closing the existing-app delivery gap](CUSTOMER-VALUE-GAP.md): a download-only styling proposal for one React/Vite page, touching one TSX file and its imported CSS module. It records source findings and implementation recommendations. It does not claim a customer build, browser trial, task pass, repository change, or demonstrated rollback occurred.

The uploaded files are data to inspect, not code to execute. The adapter must not install their dependencies, import their modules, load their Vite/PostCSS configuration, follow resource URLs, or run their scripts. Only owned fixtures may be built during development of this slice.

## Recommended source contract

The following are **product implementation recommendations**, informed by the references. They are deliberately narrower than everything React, Git, or CSS Modules can support.

### Recognize two files without executing either

Accept exactly one bounded UTF-8 TSX file and one bounded plain `.module.css` file at normalized, unambiguous relative paths. Preserve their original bytes for hashing and reversal. Reject traversal, aliases that cannot be resolved inside this two-file shape, unexpected file operations, existing trial-marker collisions, and ambiguous encoding. Do not accept package scripts, dependencies, or runtime configuration as executable discovery mechanisms.

Require a statically identifiable CSS-module import, one existing native page wrapper, and unambiguous local references for the supported heading, body, and main-action roles. Parse with trusted application code. If using a deliberately small grammar, document its accepted forms and reject everything else; broad regular-expression substitution is insufficient for arbitrary TSX or CSS.

The first adapter should reject unresolved component subtrees, spread/dynamic class composition, inline overrides on affected roles, imported styles, composition, global escapes, unsupported nesting, unknown at-rules, and declarations outside its supported grammar. These are limits of this adapter, not statements that those techniques are inherently wrong. A refusal should preserve the existing design handoff option.

### Preserve what can actually be checked in source

Allowed TSX edits should be limited to the approved wrapper modifier and any explicitly declared local role-class references. Keep element types, nesting, conditional rendering, keys, text, labels, destinations, field names, accessibility attributes, handlers, hooks, validation, state logic, and data calls unchanged. Prefer small source-span edits so bytes outside the allowed spans remain identical, instead of reprinting an entire component.

For CSS, define an explicit visual-property allowlist and pair foreground/background changes. Keep existing rules and responsive/state styles intact; append a bounded block whose selectors are tied to the trial marker and known roles. Reject rather than invent support for layout replacement, visibility changes, pointer blocking, generated content, global rules, resource loading, or `!important` escalation. Even allowed color, type, spacing, or border changes can affect perception, wrapping, and hit areas; later browser review is still necessary.

The patch must change values actually consumed by the supported fixture. A new variable that no role uses is preparation, not an implemented visual change. Conversely, a computed style change does not establish improved visual quality.

### Explain the unresolved context

Two files cannot establish every consumer of a CSS module, all outer styles, project plugins, host configuration, imported runtime behavior, or deployment setup. A new modifier can interact with external class-sensitive selectors or scripts. Treat project identity and any supplied base commit as owner-provided unless independently checked. Call the result a proposal for a supported source shape, not a verified React/Vite project upgrade; do not add a Next.js compatibility claim without its own adapter and fixture.

## Review, application, and rollback

Export a versioned contract containing the exact two paths, adapter version, design fingerprint, before/after file hashes, forward/inverse patch digests, role mapping, changed properties, checked source invariants, and unrun task IDs. Include the visible diff and instructions. Keep user text as data; the contract must not carry arbitrary commands to execute.

Before a recipient applies the proposal in an isolated working copy, require the recorded preimages to match and inspect the complete file set. A Git dry run is an additional applicability check, not a substitute for full-file hashes. Recheck identities immediately before the write, then verify the resulting bytes against the declared after-hashes. Reject mismatches atomically rather than searching for a nearby place to apply the patch. This stricter identity policy is Focus’s proposed contract, not a default Git guarantee.

For rollback, require the touched files to match the expected post-trial bytes. Apply the exact inverse and confirm the original hashes. Changes to other files must survive. If either touched file changed later, stop for selective review even if a patch engine could locate matching context. Do not overwrite the whole project or a whole later-edited file to remove a small trial.

A branch or separate working copy isolates code changes only. The recipient must identify the actual preview’s services and test data before running customer tasks. Focus’s proposed download does not create that environment or perform the recipient’s release.

## Evidence required before each claim

All entries below are proposed proof obligations, **not completed test results**.

| Claim                                      | Required proof                                                                                                                                                                                     | What it still does not prove                                                |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| “Supported source shape”                   | Accepted syntax fixtures and rejected ambiguity fixtures; exact two-file resolution; no module evaluation, configuration loading, resource fetching, or customer-script execution.                 | The submitted snapshot describes the complete customer project.             |
| “Only the declared source changed”         | Before/after hashes; comparison of noneditable source spans; syntax assertions covering unchanged tree, keys, text, props, handlers, and data expressions; exact allowed CSS declarations.         | Equivalent runtime behavior under every condition.                          |
| “The styles are connected”                 | Build an owned React/Vite fixture with pinned tooling; verify the emitted CSS and imported class mappings are consumed by its page. Run its type check separately when applicable.                 | The customer’s distinct build configuration works or the page looks better. |
| “The trial changes appearance as intended” | On an owned built fixture, compare the targeted computed styles and before/after rendering at declared widths; check hover, focus, disabled, validation, and relevant inherited styles.            | Customer usability, all surrounding pages, or excellent design.             |
| “The declared tasks still work”            | Run the same baseline and trial tasks, including success, invalid input, failure/retry, keyboard navigation, and preserved answers, using owned fixtures and test data.                            | A successful customer journey. That requires the real authorized trial.     |
| “Rollback preserves unrelated work”        | Forward/inverse round trip returns original touched bytes; edits in an unrelated file remain; later edits to either touched file trigger a refusal; a second application or inversion is rejected. | Conflict-free recovery for arbitrary later project changes.                 |
| “Evidence belongs to this proposal”        | Bind the contract digest, resulting source identity, build artifact hash, task IDs, conditions, and reported outcomes; reject stale or mismatched records.                                         | Independent truth of a recipient-supplied report.                           |

The handoff should distinguish **proposal prepared**, **source checks completed**, **owned fixture results**, **recipient-reported results**, and **customer trial observed**. None should be collapsed into a generic safety, accessibility, or launch pass.
