## Recommended parser and supported boundary

Use real syntax parsing plus a strict allowlist of recognized shapes. **Do not parse arbitrary TSX with regular expressions.** Installed capabilities are `@babel/parser` 7.29.14, PostCSS 8.5.33 and TypeScript 5.9.3. Babel's installed parser entry is about 530 KB; TypeScript's compiler entry is about 9.1 MB. The implementation now declares and pins Babel and PostCSS directly. Load this optional adapter on demand, preserving the Garden's existing lazy-loading boundary. Do not add Babel transforms, generators, config discovery or plugins that execute customer code.

- Parse TSX with Babel's explicit JSX/TypeScript syntax plugins, module source type and error recovery disabled. Do not resolve imports, transpile, evaluate, render or type-check uploaded code.
- Parse CSS with PostCSS's parser only, explicitly setting `map: false`. Its installed `previous-map` implementation can otherwise decode source-map comments and read map files in a Node environment. Reject source-map/source-URL directives as unsupported input; never pass source text to a processor/plugin/config loader.
- Use a deliberately tiny documented CSS-selector grammar on parsed rule nodes. A whole-selector allowlist such as a single ordinary local class is appropriate; regex replacement across source is not. Complex selectors require an explicit adapter extension, not permissive guessing.
- First support **React with Vite, one CSS-module page, exactly two files**. The framework answer is owner-declared. Two files cannot establish the Vite configuration, actual stylesheet order, global CSS, CSS-module naming options, route mounting or full project compatibility. No Next.js claim until a separate supported adapter and fixture exist.

## Assets, actors and trust boundaries

Protect the customer's exact source bytes, private code, current saved Focus design/answers, existing runtime behavior, recipient working copy and truthful evidence state. An owner can accidentally select stale/wrong files; a file can also contain adversarial names, deeply nested syntax, misleading comments, secrets or executable code. Imported source, role labels, comments and file paths are untrusted data, never instructions to Focus or its operator.

The flow is: local file picker → bounded byte intake → parser/recognition → confirmed role mapping → pure proposed edits → validated in-memory artifact → guarded browser download. It must not cross into customer-code execution, external resource fetching, repository/disk mutation, source autosave, account storage, telemetry containing source, or deployment. Trusted app chunks may load normally; customer file contents and referenced URLs must never be sent for processing.

The owner has clarified that the recipient developer will often be an LLM. Include fixed `AGENT-HANDOFF.md` instructions that identify the contract, allowed two-file scope, exact verification sequence and stop conditions. Uploaded source/comments, diff context, labels and project prose remain task data, even when they contain imperative text or claim higher authority. Do not promote those strings into generated instructions or commands. A digest establishes byte identity, not benevolent intent. The read-only checker cannot force an external agent to obey instructions or prevent it from changing unrelated files; state that boundary explicitly rather than describing the package as enforced containment.

## Intake and processing limits

Start with two explicit file selections, not ZIP intake. Telescope's existing private archive helpers validate raw headers before JSZip, reject duplicate/colliding paths, symlinks, encryption, ZIP64 and unsupported names, and enforce actual expanded-byte/CRC/decode limits. Do not replace that with `JSZip.loadAsync` alone if archive intake is added later; extract/reuse the tested boundary in a separate change. Current Telescope accepts built HTML/ZIP, so its public inspection function is not a source-patch parser.

Proposed initial bounds: one nonempty `.tsx` at most 128 KiB, one nonempty `.module.css` at most 64 KiB, at most 192 KiB combined; at most 20,000 AST nodes, 500 CSS rules and 2,000 declarations. File sizes must be checked before reading and actual byte counts rechecked afterwards. Strict UTF-8 decoding must reject invalid bytes; reject BOM, NUL, unsupported controls and bidi overrides rather than normalizing source. Retain CRLF/LF and end-of-file status exactly. Catch parser failures and excessive nesting as unsupported, with bounded error messages.

These are small-page limits, not promises that synchronous parsing cannot delay the UI. A real wall-time cutoff requires a dedicated worker that can be terminated; a timeout around a synchronous parser does not interrupt it. Prefer a lazy worker with a five-second ceiling and cancellation, especially before widening limits. If the first bounded implementation runs on the main thread, record that availability limitation and do not describe its timeout as enforced.

Require explicit repository-relative paths: ordinary file pickers supply basenames, not repository locations. Use a conservative ASCII path subset initially; reject absolute/drive paths, backslashes, empty/dot/traversal segments, leading dots, trailing dots/spaces, reserved device names, encoded/ambiguous separators and case-normalized collisions. Exclude dependency/build/config/secret directories. Resolve the one relative CSS import logically against the declared TSX path and require an exact match to the selected stylesheet. Never access that path on disk or fetch it. A future recipient filesystem applicator must separately reject symlinks and enforce its repository root.

Keep source only in the mounted optional panel. Do not add it to `TargetDraft`, library snapshots, progress records or local/session storage. Source can contain confidential material despite extension checks; request files without secrets/customer records and do not claim comprehensive secret detection. Display code/diffs as escaped text, never `dangerouslySetInnerHTML`, `srcDoc`, executable script or a generated resource URL.

## Recognition and exact edits

The smallest practical supported TSX shape is one default-exported, named synchronous function with one direct top-level JSX return and one native `main`, `section` or `div` wrapper. Require one default relative CSS-module import and statically identifiable heading, supporting text and primary action, using native elements and direct `styles.className` references. Reject fragment/conditional roots, ambiguity, dynamic/spread class composition, inline style overrides on targeted nodes and unresolved custom components inside the affected subtree. Preserve the wrapper's element type, children, keys and position; do not rebuild the tree or introduce another wrapper.

AST matching must bind the style reference to the actual import. Reject shadowed/reassigned aliases, module-object mutation and unsupported alias use; matching an identifier's spelling is insufficient. Each role must identify one intended node and one explicit local class. Reject repeated/ambiguous role-class consumers. Show actual static labels for owner confirmation; dynamic labels that cannot be identified are an unsupported mapping, not fabricated sample copy.

For CSS, reject `:global`, `:export`, `:import`, `composes`, nesting, at-rules, imports, important overrides and unmodeled selector/cascade forms. Preserve permitted focus/interaction styling. If a supported state selector changes a property the trial would override, refuse it until that state is explicitly modeled; a later higher-specificity base rule must not silently erase hover/disabled/focus feedback. This includes color or font-family state declarations inherited from a recognized ancestor. The initial direct-role check missed that inheritance case; the reviewed implementation now refuses it and has regressions for wrapper hover color and ancestor focus-within fonts.

Append a unique local modifier to the existing wrapper at its validated AST expression span. Append only fixed generated selectors and allowlisted visual declarations to the matched CSS module. Use normalized design values, not arbitrary supplied CSS. Do not append to unrelated global styles or modify routes, dependencies, imports outside the defined CSS-module relationship, authentication, data operations, handlers, field names, validation, labels, destinations or application configuration.

Avoid inherited wrapper color/font/custom-property changes that affect unmodeled descendant controls. Pair changed foreground/background roles explicitly. Layout, typography and background changes can still affect wrapping, transparent descendants and interaction geometry; state those limits and required task checks. CSS-module locality alone does not prove isolation from inheritance or the surrounding cascade.

Preserve all source outside exact permitted spans byte-for-byte. Babel offsets index UTF-16 strings, not UTF-8 bytes: either translate offsets carefully or splice the strictly round-trippable decoded string and re-encode it. Do not use an AST pretty-printer for the whole customer file. Reparse the proposed files, check the expected modifier/rules, compare protected source spans and reject any mismatch.

## Patch identity, reversal and delivery

Use a strictly validated versioned contract with fixed schema/adapter identifiers, normalized design fingerprint, original two-file snapshot digest, selected paths, exact before/after SHA-256 values, exact edit/patch digests, role mapping, changed properties and required task IDs. Initial task/evidence states remain `not-run`; owner statements and manually supplied repository revisions are labelled unverified. Do not embed arbitrary executable commands from source, paths or owner prose.

An in-memory application helper must check **both original hashes before any changes**, apply only its recognized edits, and verify both expected output hashes. Inverse application checks both after-hashes before restoring exact originals. A touched-file mismatch, partial application, existing modifier collision, repeat application or changed design/context must stop, even if a patch tool could apply using context/fuzz. Unrelated files are never part of the operation and remain untouched.

Deliver fixed artifact filenames such as `forward.patch`, `rollback.patch`, `trial-contract.json` and `README.md` inside a new trial folder, not customer paths that a ZIP extractor could overwrite. An ordinary unified patch does **not** enforce the contract's whole-file hashes; `git apply --check` tests applicability, not exact identity. If no guarded recipient applicator is shipped, state that the recipient must verify the hashes before application and that Focus has only enforced its in-memory preparation. Do not claim external preimage enforcement or automatic safe application. Avoid instructions using fuzzy merge, `--reject`, whitespace-ignore, `--unsafe-paths`, hard reset or blanket file restoration.

Reuse Target's current owner/design/draft revalidation immediately before and after asynchronous preparation and immediately before download. Capture source bytes, declared paths, confirmed roles and generation identity too. Replacement, path/role edits, design/plan changes, cancellation, owner lock, step exit and unmount must synchronously invalidate pending work. A stale completion cannot revive old proposals, export them or set a success flag. Preserve the existing ordinary handoff flow and its independent status.

## Threats and acceptance evidence

| Failure or threat                                                              | Required control / regression                                                                                                                                          |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Selected source executes or fetches resources                                  | Parser-only path; no module evaluation, DOM rendering, config/plugin load or network resolution. Malicious code and source-map fixtures cause no execution/read/fetch. |
| Oversized, ambiguous or hostile files freeze processing or address wrong files | Actual byte and syntax bounds, strict encoding/path checks, cancellation/worker limit where implemented; reject duplicates and CSS import mismatch.                    |
| Name-based matching changes the wrong component                                | AST import binding, no shadow/mutation, unique native role mapping, ambiguity refusals.                                                                                |
| Patch alters behavior or unmodeled CSS state                                   | Exact outside-span equality and preserved element/attribute/handler topology; strict CSS/state grammar; owned fixture task tests before/after.                         |
| Stale patch or rollback overwrites later work                                  | Exact whole-file hash gate and all-or-nothing in-memory operation; drift/partial/double-apply tests; unrelated-file preservation.                                      |
| Delayed reads/downloads cross design or owner boundaries                       | Existing Target revalidation plus synchronous source generation invalidation; deferred-race and owner-lock regressions.                                                |
| Artifact or UI falsely certifies a customer app                                | Separate prepared/static/fixture/recipient-reported/browser states; no automatic launch evidence or release approval.                                                  |

Owned fixtures should prove the added CSS-module class is present in rendered component output and the corresponding styles are emitted by an actual React/Vite build. Exercise success, invalid input, failure/retry and retained form values before and after using test data with no external effects. Forward then inverse must restore exact touched bytes; changing either touched file must refuse reversal while unrelated changes survive.

No supplied customer code is installed or executed for these tests. A fixture build is not customer compatibility, a component test is not browser acceptance, and a hash binds bytes rather than verifying a report's claims. The eventual customer milestone still needs its actual isolated project, real task/error/permission journeys, responsive/keyboard/zoom review and demonstrated selective rollback.

## Implementation review boundary

The current implementation uses a lazy optional panel, synchronous bounded parsers, in-memory proposal generation and a separate proposal ZIP. It does not contain a filesystem writer or an interruptible parser worker. Cancellation suppresses delayed reads, hashes and downloads; it cannot interrupt synchronous parsing already in progress. The shipped Node verifier performs bounded read-only file checks, refuses observed symlink paths and validates companion hashes. Its path contract matches the browser intake's 200-character, 80-character-segment and 12-segment bounds. Application and reversal remain explicit recipient actions with the point-in-time limitations above.

Independent review also corrected the recipient's initial path-rule drift and the UI's initial implication that font changes preserve rendered layout. The proposal now describes preserved layout rules and pending wrapping checks. It refuses a proposal when all eight directly declared role values already match. These checks narrow known failure modes; they do not certify an unseen customer application or an external LLM's behavior.
